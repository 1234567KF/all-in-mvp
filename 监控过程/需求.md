# Pipeline Monitor CLI - 产品需求文档

## 1. 概念与愿景

**Pipeline Monitor** 是一个命令行工具，通过监听文件系统变化和进程事件，实现对 Multi-Agent Pipeline 的实时监控、告警与可视化报告。

与其依赖人工追加日志的脆弱机制不同，本工具**主动感知** Pipeline 活动，让 Coordinator 和开发者实时掌握执行状态。

---

## 2. 核心问题

| 当前 Skill 设计的问题 | 解决方案 |
|----------------------|---------|
| 依赖人工追加日志，易遗漏 | 监听文件系统 + Hook 事件 |
| 事后记录，无法实时监控 | 事件驱动，实时感知 |
| 纯文本无法做智能分析 | 结构化数据 + 实时 Dashboard |

---

## 3. 功能范围

### 3.1 核心功能

| 功能 | 描述 |
|------|------|
| **Agent 事件追踪** | 监听 `.qoder-flow/` 目录变化，自动识别 Agent spawn/完成 |
| **Token 成本监控** | 记录每个 Agent 的输入/输出 Token 数量、模型类型、成本计算 |
| **H2A 消息监控** | 记录 Human → Agent 的指令交互（输入消息、上下文注入） |
| **A2A 消息监控** | 记录 Agent → Agent 的协作交互（上下文传递、依赖请求） |
| **执行链路还原** | 根据事件序列还原完整 Pipeline 执行链路 |
| **状态可视化** | 实时终端输出 Pipeline 进度（类似 `top` 或 CI Dashboard） |
| **异常告警** | Agent FAILED / 超时 / 依赖阻塞时发出告警 |
| **报告生成** | 执行完成后生成结构化报告（JSON/Markdown） |
| **多 Pipeline 管理** | 同时监控多个 Pipeline，支持多会话并行监控 |

### 3.2 用户场景

```
场景 A：开发者启动 Pipeline 后，在终端实时观察各 Agent 执行状态
场景 B：Coordinator 远程查看 Pipeline 执行进度
场景 C：执行完成后自动生成执行报告
场景 D：同时运行多个 Pipeline（多会话），在统一 Dashboard 查看所有 Pipeline 状态
```

## 4. 技术方案

### 4.1 架构

```
┌─────────────────────────────────────────────────────────────────────┐
│                      Pipeline Monitor                              │
├─────────────────┬───────────────────┬─────────────────┬────────────┤
│ FileWatcher      │ EventParser       │ TokenTracker    │ Reporter   │
│ (chokidar)      │ (解析+去重)       │ (成本计算)      │ (JSON/MD)  │
├─────────────────┴───────────────────┴─────────────────┴────────────────┤
│                    MessageTracer (H2A/A2A)                          │
├─────────────────────────────────────────────────────────────────────┤
│                    Drizzle ORM + SQLite                              │
├─────────────────────────────────────────────────────────────────────┤
│                    WebDashboard (Express + Socket.io)              │
│                    [独立运行时，非 CLI 依赖]                        │
└─────────────────────────────────────────────────────────────────────┘
```

### 4.2 事件来源

| 来源 | 说明 |
|------|------|
| **文件系统监听** | 监听 `.qoder-flow/events/` 下新文件（JSON 格式），跨平台使用 chokidar |
| **命令行参数** | `pmonitor --spawn <agent-id>` 手动发送事件 |
| **Webhook API**（可选） | 提供 HTTP 端点接收外部事件 |

### 4.3 事件格式

#### 4.3.1 Agent 事件

```json
{
  "eventId": "uuid",
  "pipelineId": "auth-mvp-20260521",
  "type": "SPAWNED | DONE | FAILED",
  "agentId": "backend-agent-1",
  "agentRole": "后端 Agent-1（认证与权限专家）",
  "model": "claude-sonnet-4-20250514",
  "skills": ["kf-mvp-auth-implementation", "kf-mvp-backend-tdd"],
  "inputs": ["src/modules/auth/"],
  "expectedOutputs": ["src/modules/auth/routes.ts"],
  "timestamp": "2026-05-21T10:30:00Z",
  "metadata": {}
}
```

#### 4.3.2 Token 事件（TokenMetric）

```json
{
  "eventId": "uuid",
  "pipelineId": "auth-mvp-20260521",
  "type": "TOKEN_USAGE",
  "agentId": "backend-agent-1",
  "model": "claude-sonnet-4-20250514",
  "tokens": {
    "input": 12500,
    "output": 3200,
    "cacheCreation": 450,
    "cacheRead": 1200
  },
  "cost": {
    "inputCost": 0.0125,
    "outputCost": 0.0096,
    "totalCost": 0.0221,
    "currency": "CNY"
  },
  "timestamp": "2026-05-21T10:32:15Z"
}
```

#### 4.3.3 H2A 消息事件

记录 Human 与 Agent 之间的交互（指令下达、上下文注入）。

**sender 定义**：Coordinator Agent 代表 Human 发送指令时，记录为 H2A 消息。

```json
{
  "eventId": "uuid",
  "pipelineId": "auth-mvp-20260521",
  "type": "H2A_MESSAGE",
  "agentId": "coordinator-agent",
  "direction": "HUMAN_TO_AGENT",
  "content": {
    "prompt": "开始执行 Stage3，请分配后端任务",
    "context": {
      "stage": "Stage3",
      "availableAgents": 3
    }
  },
  "tokens": {
    "input": 850,
    "output": 1200
  },
  "timestamp": "2026-05-21T10:00:00Z"
}
```

#### 4.3.4 A2A 消息事件

记录 Agent 与 Agent 之间的协作交互（上下文传递、依赖请求）。
```json
{
  "eventId": "uuid",
  "pipelineId": "auth-mvp-20260521",
  "type": "A2A_MESSAGE",
  "fromAgent": "backend-agent-1",
  "toAgent": "frontend-agent-1",
  "purpose": "CONTEXT_DELIVERY | DEPENDENCY_REQUEST | RESULT_SHARING",
  "content": {
    "summary": "API 接口定义已完成",
    "artifactIds": ["api-contract-v2.yaml"],
    "dependentModules": ["auth", "user"]
  },
  "tokens": {
    "input": 2100,
    "output": 1800
  },
  "timestamp": "2026-05-21T10:45:30Z"
}
```

```

```

### 4.5 使用方式

```bash
# 启动监控（包含 Token 和消息追踪）
pmonitor start

# 监控指定目录
pmonitor start --project ./my-mvp

# 生成执行报告（包含 Token 成本和消息统计）
pmonitor report --output pipeline-report.md

# 手动发送 Agent 事件
pmonitor spawn --agent backend-agent-1 --role "认证专家"
pmonitor done --agent backend-agent-1 --outputs src/modules/auth/
pmonitor fail --agent backend-agent-1 --error "编译失败"

# 手动发送 Token 使用事件
pmonitor token --agent backend-agent-1 --input 12500 --output 3200

# 手动发送 A2A 消息事件
pmonitor a2a --from backend-agent-1 --to frontend-agent-1 --purpose CONTEXT_DELIVERY
```

## 7. 验收标准


### 7.1 CLI 核心功能

- [ ] `pmonitor start` 能监听目录变化（使用 chokidar）并解析 JSON 事件
- [ ] Dashboard 实时显示 Pipeline 各 Agent 状态（刷新间隔 ≤ 1 秒）
- [ ] `pmonitor spawn/done/fail` 命令能正确发送带 pipelineId 的事件
- [ ] 执行完成后 `pmonitor report` 能生成 Markdown 报告

### 7.2 Token 与消息追踪
- [ ] **Token 追踪**：能记录并汇总每个 Agent 的输入/输出 Token 及成本
- [ ] **H2A 追踪**：能记录人与 Agent 的交互消息及 Token 消耗
- [ ] **A2A 追踪**：能记录 Agent 间消息传递及 Token 消耗

### 7.3 Web UI 功能
- [ ] **报告含成本分析**：输出 Markdown 报告包含 Token 成本明细和模型分布
- [ ] **Web UI**：黑色主题 shadcn/ui，支持实时 Agent 状态、Token 成本、消息流可视化
- [ ] **多 Pipeline 管理**：支持同时监控多个 Pipeline，列表页显示所有运行中的 Pipeline

### 7.4 异常处理
- [ ] **异常告警**：Agent FAILED 时触发告警
- [ ] **超时检测**：Agent 运行超过 30 分钟（可配置）未完成时告警
- [ ] **依赖阻塞告警**：Agent 等待依赖未完成时显示阻塞状态

### 7.5 数据与幂等性
- [ ] **事件幂等性**：相同 eventId 的事件不会重复处理
- [ ] **执行链路还原**：能根据事件序列还原完整 Pipeline 执行链路

## 8. 备选方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| **A: CLI 工具**（本方案） | 轻量、无外部依赖、易集成 | 无 Web UI |
| B: Skill + 定时轮询 | 不改架构 | 实时性差、资源浪费 |
| C: 独立 Web 服务 | 功能强大、可视化好 | 架构复杂、需要数据库 |


## 9. Token 成本模型

> 所有成本以 **人民币 (CNY)** 计价，默认汇率 1 USD = 7.2 CNY（可配置）

### 9.1 支持的模型定价（人民币/百万tokens）

| 模型 | 输入 (¥/M) | 输出 (¥/M) | 缓存创建 | 缓存读取 |
|------|-------------|------------|--------|-----------|
| claude-sonnet-4-20250514 | 21.60 | 108.00 | 27.00 | 2.16 |
| claude-opus-4-20250514 | 108.00 | 540.00 | 135.00 | 10.80 |
| claude-haiku-4-20250514 | 1.80 | 9.00 | 2.16 | 0.22 |

### 9.2 成本计算公式

```
总成本 = (input_tokens × input_price + output_tokens × output_price 
          + cache_creation_tokens × cache_creation_price 
          + cache_read_tokens × cache_read_price) / 1,000,000
```

## 10. H2A/A2A 消息追踪设计

### 10.1 消息类型定义

| 消息类型 | 说明 | 典型场景 |
|----------|------|----------|
| **H2A_INSTRUCTION** | 人类向 Agent 发出指令 | Coordinator 分配任务 |
| **H2A_CONTEXT_INJECT** | 人类注入上下文 | 补充需求信息 |
| **H2A_APPROVAL** | 人类审批通过 | 阶段验收 |
| **A2A_CONTEXT_DELIVERY** | Agent 向下游传递上下文 | 架构师→开发者 |
| **A2A_DEPENDENCY_REQUEST** | Agent 请求上游依赖 | 前端请求后端 API |
| **A2A_RESULT_SHARING** | Agent 共享产出结果 | 测试结果同步 |


### 10.2 消息流可视化

```
┌─────────┐         H2A         ┌─────────────┐
│  Human  │ ───────────────────→ │ Coordinator │
└─────────┘                      └──────┬──────┘
                                        │
                    A2A                │
     ┌───────────────────────────────────┼───────────┐
     ▼                                   ▼           ▼
┌─────────┐                       ┌─────────┐ ┌─────────┐
│Backend-1│← ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─│Frontend-1│ │  Mock   │
└────┬────┘                       └─────────┘ └─────────┘
     │ A2A                              A2A
     ▼                                  ▼
┌─────────┐                       ┌─────────┐
│Backend-2│                       │Frontend-2│
└─────────┘                       └─────────┘
```

### 10.3 消息统计指标

| 指标 | 说明 |
|------|------|
| H2A 消息总数 | 人类向 Agent 发出的指令数量 |
| A2A 消息总数 | Agent 间协作消息数量 |
| 消息 Token 消耗 | 每条消息的输入/输出 Token |
| 依赖链深度 | A2A 消息的最长传递路径 |
| 阻塞时间 | 因 A2A 依赖导致的等待时间 |

## 12. 超时与告警配置

### 12.1 超时阈值

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `agentTimeout` | 30 分钟 | 单个 Agent 运行超时阈值 |
| `pipelineTimeout` | 120 分钟 | Pipeline 总运行超时 |
| `alertDebounce` | 5 秒 | 告警防抖间隔 |

### 12.2 告警触发条件

| 条件 | 告警级别 | 处理方式 |
|------|----------|----------|
| Agent DONE | INFO | 记录完成时间 |
| Agent FAILED | ERROR | 立即告警 + 通知 |
| Agent 超时 | WARNING | 超时告警 + 可选终止 |
| 依赖阻塞 > 10 分钟 | WARNING | 阻塞告警 |

### 13.1 状态定义

| 状态 | 说明 |
|------|------|
| **CREATED** | Pipeline 已创建，等待启动 |
| **RUNNING** | 正在执行 |
| **PAUSED** | 暂停（可恢复） |
| **COMPLETED** | 全部 Agent 完成 |
| **FAILED** | 有 Agent 失败 |
| **CANCELLED** | 被手动取消 |

### 13.2 生命周期事件

```
CREATED → RUNNING → COMPLETED
              ↓
           FAILED
              ↓
         [修复] → RUNNING
              ↓
         CANCELLED
```

### 13.3 事件幂等性

- 每个事件携带唯一 `eventId`
- 接收端根据 `eventId` 做去重
- 相同 `pipelineId + agentId + type` 的最新事件覆盖旧事件

```
    └── {pipelineId}-{timestamp}.md
```
