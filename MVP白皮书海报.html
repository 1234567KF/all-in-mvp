决策原则

串行 vs 并行

明确什么时候必须串行，什么时候可以并行，最大化流水线效率

⟳

必须串行

  • PRD 未锁定前：所有 Stage2 Agent 必须等待产品经理完成
  • ↺ 拷问审查循环未通过前：Mock、TDD 必须等待产出物锁定
  • 模块间强依赖：如订单依赖用户，用户模块必须先完成
  • 接口契约变更：依赖该接口的所有 Agent 必须同步
  • 集成测试阶段：必须等前后端都完成才能开始
⇅

可以并行

  • ③a Mock、③b-1 测试、③b-2 场景测试：↺ 通过后三者同时启动
  • ③b-1 内部：最多 2 Agent 按模块平分并行写单模块测试
  • 无依赖模块后端开发：用户管理 vs 类目管理同时进行
  • 前端 vs 后端：Mock 就绪后前端即可并行开发
  • Stage3 测试补充：事件驱动，与后端开发同步
质量保障

门禁与度量

每个阶段都有硬约束门禁，确保产出物质量

Stage1 → Stage2

  • PRD 文件 > 1KB、9 个章节全存在
  • MECE 完整性检查通过
  • 6 项质量门禁全部通过

Stage2 → Stage3

  • 所有产出物存在且 MD5 与锁定一致
  • YAML/JSON 语义可解析
  • ↺ 拷问审查全部通过

Stage3 → Stage4

  • 所有模块目录存在 DONE 标记
  • schema.sql 语法正确
  • L1-L5 测试全部通过

Stage4 → 交付

  • 集成测试报告非空
  • 0 个 P0/P1 Bug
  • Mock-后端一致性验证通过
