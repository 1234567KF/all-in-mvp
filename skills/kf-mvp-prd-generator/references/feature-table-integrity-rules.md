# 功能需求完整性强制规则

> **用途**：生成 Chapter 6 功能需求时加载。本文档是 AI 的"反偷懒清单"——告诉 AI 什么算偷懒、如何自查、不通过会怎样。

---

## 核心原则

**一个功能点 = 一个完整规格块 = 8 个维度全部填满。**

这 8 个维度（描述、验收标准、业务规则、交互模式、状态流转、字段规格、数据校验规则、数据权限）原本分布在标准 PRD 的多个独立章节中，AI 在章节之间跳跃时天然倾向于跳过内容。合并到一个功能块中后，每个缺失维度都是可见的空白——没有地方可以隐藏。
其中 **维度6 字段规格** 和 **维度8 数据权限** 是条件维度（仅当功能涉及页面或权限控制时强制），但更常见的是 AI 选择性地"忘记"输出它们——本文件的规则就是要让这种遗忘变得可见和痛苦。

---

## 逐维度最低标准

### 1. 描述

| 检查项 | 最低标准 |
|--------|---------|
| 字符数 | ≥ 30 个中文字符 |
| 内容要求 | 必须回答：做什么 + 为什么需要 + 与哪些功能关联 |
| 禁止模式 | `"管理XX"`、`"查看XX"`、`"XX列表"`、`"XX功能"` |

**偷懒示例** → **重写示例**：

| 偷懒 | 重写 |
|------|------|
| "管理用户信息" | "提供用户账号的创建、编辑、禁用/启用和密码重置功能。用户信息是系统权限体系的基础，所有业务操作均需关联有效用户。支持按角色批量分配权限。" |
| "查看订单列表" | "以分页表格展示所有订单，支持按订单号、客户名称、下单日期范围、订单状态多条件组合筛选。列表默认按下单时间倒序排列，每页显示 20 条记录。点击订单号可跳转至订单详情页。" |

### 2. 验收标准

| 检查项 | 最低标准 |
|--------|---------|
| 格式 | Gherkin Scenario 格式，Given/When/Then 三段齐全 |
| 执行边界 | 每个 Then/And 标注 (Frontend) 或 (Backend) |
| 覆盖 | 单功能级别，验证该功能的核心行为 |

**偷懒示例** → **重写示例**：

| 偷懒 | 重写 |
|------|------|
| "功能正常" | `Scenario: AC-001 - 新增用户成功` → `Given 管理员已登录` → `When 填写有效用户信息并提交` → `Then 列表刷新显示新用户 (Frontend)` → `And 后端返回 201 (Backend)` |

### 3. 业务规则

| 检查项 | 最低标准 |
|--------|---------|
| 数量 | P0 功能 ≥ 2 条，P1 功能 ≥ 1 条，P2 功能 ≥ 0 条 |
| 格式 | IF-THEN 格式：`IF 条件 THEN 结果` |
| 完整性 | 每条规则含：违反时处理方式 + 前置条件 |
| 禁止模式 | "按照业务规则处理"、"根据配置"、"视情况而定" |

**偷懒示例** → **重写示例**：

| 偷懒 | 重写 |
|------|------|
| "按照业务规则校验" | `BR-001: IF 订单金额 > 用户信用额度 THEN 订单提交失败`，违反时提示"超出信用额度，请联系客服"，前置条件：用户已登录且已完成实名认证 |

### 4. 交互模式

| 检查项 | 最低标准 |
|--------|---------|
| 步骤数 | ≥ 2 步（每步 = 用户操作 → 系统响应） |
| 格式 | 步骤编号 | 用户操作 | 系统响应 | 备注 |
| 覆盖 | 至少覆盖：正常操作流程 + 加载态 + 空态 + 错误态 |

**偷懒示例** → **重写示例**：

| 偷懒 | 重写 |
|------|------|
| "点击按钮→弹出弹窗" | 1. 点击"新增"→弹出新增表单弹窗，表单字段按配置加载；2. 填写必填字段后点击"保存"→前端校验通过后提交后端，按钮显示 loading；3. 保存成功→弹窗关闭，列表刷新，顶部提示"新增成功"；4. 保存失败→弹窗不关闭，错误信息显示在表单顶部 |

### 5. 状态流转

| 检查项 | 最低标准 |
|--------|---------|
| 适用判定 | 只要实体有状态字段（即使只是启用/禁用），就必须输出 |
| 必须输出 | 状态列表 + Mermaid stateDiagram-v2 流转图 + 状态-操作-权限映射表 |
| 异常回退 | 状态图 MUST 包含异常回退路径（如审批驳回、校验失败） |
| 不适用时 | 明确写"不适用 — 无状态流转"，不得留空或写"—" |

**偷懒示例** → **重写示例**：

| 偷懒 | 重写 |
|------|------|
| 留空或写"—" | 即使只有"启用/禁用"两个状态，也要输出：状态列表（启用、禁用）、流转图（`[*]→启用:创建`、`启用→禁用:管理员禁用`、`禁用→启用:管理员启用`）、映射表（启用→可禁用、禁用→可启用） |

### 6. 字段规格

| 检查项 | 最低标准 |
|--------|---------|
| 适用判定 | 功能涉及页面展示时强制输出（列表/表单/统计/特殊页面） |
| 页面类型 | 必须先通过 Q5a/Step 6.5 确定页面类型，再输出对应规格表 |
| 列表型完整 | 含查询字段表 + 列表字段表 + 操作按钮表（每表≥3行示例数据） |
| 表单型完整 | 含全字段输入类型/数据来源/必填/校验/条件显示/联动/3态差异（新增/编辑/查看） |
| 统计型完整 | 含统计字段计算逻辑 + 展示形式（数值/百分比/特殊格式）+ 筛选联动 |
| 特殊页面完整 | 含页面布局描述 + 交互方式 + 特殊说明 |
| 联动规则 | MUST 描述字段间的依赖关系（如：选择省份后自动过滤城市选项） |
| 条件显示 | MUST 描述字段显示/隐藏的条件（如：仅当为"企业用户"时显示"企业名称"字段） |
| 操作按钮条件 | MUST 描述按钮的显示条件和权限，如"仅已审核状态可回退" |

**偷懒示例** → **重写示例**：
| 偷懒 | 重写 |
|------|------|
| 只写"字段见原型" | 输出完整字段规格表，含输入类型、校验规则、新增/编辑/查看三态差异 |
| 只写"有联动"不写具体 | 描述联动逻辑：选择"省份"="北京"时，"城市"下拉框仅显示北京的区 |

### 7. 数据校验规则

| 检查项 | 最低标准 |
|--------|---------|
| 数量 | 每个功能 ≥ 2 条校验规则 |
| 格式 | 校验对象 | 校验类型 | 校验规则 | 错误提示 | 校验位置 |
| 校验类型枚举 | 格式校验 / 范围校验 / 存在校验 / 唯一校验 / 关联校验 / 业务规则校验 |
| 位置标注 | 每个规则 MUST 标注 前端/后端/双端 |
| 禁止模式 | "前端校验"、"系统校验"等泛化描述 |

**偷懒示例** → **重写示例**：
| 偷懒 | 重写 |
|------|------|
| "前端校验" | `手机号 | 格式校验 | 正则: ^1[3-9]\d{9}$ | 请输入11位有效手机号 | 前端` |

### 8. 数据权限

| 检查项 | 最低标准 |
|--------|---------|
| 适用判定 | 涉及多角色或行级数据隔离时强制，全系统共享时写"不适用" |
| 必须输出 | 数据范围 + 可见角色 + 可操作角色 + 权限粒度（全表/行级/字段级） |

## 逐功能自检表

生成每个功能块后，MUST 运行以下检查。任何一个 ❌ 都必须返回修改。

```
功能编号：F-XXX  优先级：P0/P1/P2

□ 1. 描述 ≥ 30 字符？不含"管理XX"等泛化短语？         [✅/❌]
□ 2. 验收标准 Given/When/Then 齐全？标注了 Frontend/Backend？ [✅/❌]
□ 3. 业务规则 ≥ 2条(P0) / ≥1条(P1)？IF-THEN 格式？含违反处理？ [✅/❌]
□ 4. 交互步骤 ≥ 2步？含加载/空/错误态？                   [✅/❌]
□ 5. 状态流转：涉及状态→有图+映射表？不涉及→明确标注？    [✅/❌]
□ 6. 无空单元格或"—"占位符？                              [✅/❌]
□ 7. 字段规格：输出页面类型对应规格表？含操作按钮条件显示？  [✅/❌]
□ 8. 数据校验规则：每功能≥2条？含校验类型+规则+位置？      [✅/❌]
□ 9. 数据权限：涉及多角色→输出权限表？全系统共享→写"不适用"？[✅/❌]
```

## 按频率排列的 AI 偷懒模式（从高到低）

AI 在生成 PRD 时最容易跳过的维度排序：

1. **业务规则**（跳过率最高）— AI 倾向于写"根据业务规则校验"而不是列出具体规则
2. **交互模式的错误态** — AI 只写正常流程，不写加载/空/错误三态
3. **状态图的异常回退** — AI 只画正常流转，不画审批驳回、校验失败等回退
4. **描述的具体性** — AI 用"管理XX"节约 token
5. **验收标准的 Frontend/Backend 标注** — AI 忘记标注执行边界
6. **字段规格空洞** — AI 在复杂专题中输出字段表，但在普通页面中省略
7. **校验规则泛化** — AI 写"前端校验"而不是具体的规则表达式
8. **数据权限跳过** — AI 认为"全系统共享"就不需要输出，但多角色场景下经常遗漏

**对策**：生成时优先关注排名靠前的维度，生成后反向检查（先查业务规则，最后查描述）。

## 模块级完整性门禁

每个模块的功能需求生成完成后，运行以下模块级检查：

| 检查项 | 标准 | 不通过处理 |
|--------|------|-----------|
| 功能点数量 | 每个页面 ≥ 2 个功能点 | 补充功能点 |
| P0 功能占比 | P0 功能 ≥ 模块功能的 30% | 重新评估优先级 |
| 业务规则总数 | 模块内所有功能的业务规则之和 ≥ 5 条 | 补充规则 |
| 跨功能状态一致性 | 同一实体在不同功能中状态列表一致 | 统一状态定义 |
| 页面类型覆盖率 | 所有页面均已归类（列表型/表单型/统计型/特殊页面） | 补充页面归类 |

## 错误等级

| 等级 | 描述 | 处理方式 |
|------|------|---------|
| **阻断** | 功能块缺少某个维度（空白/未输出） | 必须补充后继续 |
| **严重** | 维度存在但内容不达标（如描述 < 30 字符） | 必须重写 |
| **警告** | 内容达标但可以更深（如交互步骤只写了 2 步但功能复杂） | 建议补充，不阻断 |

**阻断和严重级别的条目必须在进入下一模块前修复。警告级别可记录到待优化清单中。**
