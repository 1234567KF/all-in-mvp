决策原则

串行 vs 并行

明确什么时候必须串行，什么时候可以并行

⟳

什么时候必须串行？

  • PRD 未锁定前：所有 Stage2 Agent 必须等待
  • ↺ 拷问审查循环未通过前：Mock、TDD 必须等待
  • 模块间强依赖：如订单依赖用户
  • 接口契约变更：所有依赖 Agent 必须同步
  • 集成测试阶段：必须等前后端都完成
⇅

什么时候可以并行？

  • ③a Mock、③b-1 单模块测试、③b-2 场景测试：↺通过后并行
  • ③b-1 内部：最多 2 Agent 按模块平分
  • 无依赖模块的后端开发：用户管理 vs 类目管理
  • 前端 vs 后端：Mock 就绪后前端即可并行
  • Stage3 测试补充：事件驱动，与后端同步
调度策略

依赖图 + 专家匹配

Pipeline Coordinator 每轮调度严格三步走：依赖图筛选 → 专家匹配 → 兜底分配

01

依赖图筛选

扫描所有模块，筛选「依赖已满足 且 未分配」的模块。启动时校验无环 + 隐式依赖 + 数据竞争。

拓扑排序 循环检测 孤儿模块
02

专家领域匹配

每轮按 Agent 擅长领域优先分配。认证权限 → Backend-1，业务核心 → Backend-2，工具配置 → Backend-3。

领域匹配 被依赖优先级 确定性排序
03

兜底分配

无匹配专家空闲时，降级分配给任意空闲 Agent。确保不会因等待特定专家而阻塞。

降级兜底 无阻塞
质量保障

门禁与度量

每个阶段都有硬约束门禁，确保产出物质量

Stage 1 → Stage 2

  • PRD 文件 > 1KB
  • 9 个章节标题全存在
  • MECE 检查通过

Stage 2 → Stage 3

  • 所有产出物存在
  • MD5 与锁定时刻一致
  • YAML/JSON 语义可解析

Stage 3 → Stage 4

  • 所有模块目录存在 DONE 标记
  • schema.sql 语法正确
  • L1-L5 测试全部通过

Stage 4 → 交付

  • 集成测试报告非空
  • 0 个 P0/P1 Bug
  • Mock-后端一致性验证
